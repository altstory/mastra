# 分集大纲

## 金字塔式拆解

需要分层时可从整体体验拆到幕、章和事件；单元、群像、日常或探索作品也可按关系、地点、时间或任务组织，不强制采用金字塔。说明各部分承担的作用即可。

## 大纲要包含

- **章节推进与收尾**：按作品选择悬念、局部完成、情感余韵、观察或休息，不强制每章悬崖式收尾。
- **场景事件描述**：事件级别；多场景时可细化到场景。
- **互动节点标记**：位置、方向、反馈、影响。
- **行动与分支**：存在分支时说明条件与结果，也记录探索、制作、协作等行动；表达型或局部差异不必扩成独立长线。
- **关键台词**：帮助理解体验。
- **终点**：依据作品承诺写单一、多种或开放终点，不以数量评价完整性。

## 多结局

仅在作品需要时设计多结局。数量依据人物差异、行动后果、篇幅和制作预算，不规定中间或最终结局配额；一个结局也可以承接多种过程。每个设计中的结局写明：

- 触发条件；
- 情感体验；
- 最精彩的部分；
- 与核心体验的呼应。

## 生成策略

先复用已知的章节数、总时长与方向，生成精简的情节序列，用 outline 预览展示关键事件、选择和钩子。存在影响节奏或结局的新取舍时，放进 ask_user.preview 请用户就具体内容反馈，再展开详细分场；不要在用户看过核心情节前默默写完全部细节。保持整体因果与风格一致，扩展时依据同一份概要。用户明确授权直接完整生成时照做，仍展示中间成果。

## 跨集推进

- 区分三类事项：入场前已完成的事件、本集新事件、仍待兑现的承诺。
- 已确认的发现、身份或路线是后续行动的**前提**，不再作为下一集的发现、目标或离场成果。按事件的含义去重，不要因为素材里既有摘要又有详写就分配两次。
- 举例：第一集已经确认主角重生，第二集就直接推进下一项行动或首次能力实验，不要再通过噩梦、再次醒来、核对日期或短回顾重新确认。只保留真正新增的能力边界、障碍和后果。
- 大纲里的计划只表示计划，不能当作已经写出的剧情证据。

## 时间与结果

- 交易、运输之类的过程可以省略，不必独立成场；但正文或当前路线已选的反馈里，必须明确时间推进、完成的结果，以及它对后续行动的影响。
- 保留设定里的相对时间、期限和前置条件；约定或打算不等于完成。
- 结果要先于依赖它的不可逆行动。例如物资验收、入库完成之后才能封门；不能开头说已备齐，封门之后又把最后一批入库写成待办。
- 尚待互动决定的结果，要由所选的行动和反馈来确立，不能在选择之前预先完成，也不能把未选路线当成事实。

## 节拍与钩子

- 「压抑 → 蓄势 → 爆发」适用于部分强情绪作品；也可用发现、靠近、疏离、平静、失控或修复组织节奏。收尾兑现当集承诺，不为加钩子破坏自然终点。
- 危机、信息、情感、身份是常见钩子示例，亦可由动作未完成、空间变化、关系期待或新问题推动；按内容需要安排，不逐章填类型指标。
- 可选的爽点类型：升级、打脸、收获、反转、情感、揭秘、绝境逢生。优先标出情绪势能高的节点。

## 知识库参考

需要爽点公式和节奏规则时，用知识库检索「爽点与快节奏写作规范」，以及对应题材页面里的章节规划（按集数折算）。

搭主线和分集时，再检索：「预期拉扯四步法（主线蓝图）」 「期待四循环与循环升级六维度」 「梗概四步检测法」 「810大纲与预期拉扯的映射及节奏重排」 「分集细纲：期待四循环的节奏分配」 「定锚点与十里程碑：事件驱动大纲搭建」 「十序列与八要素咬合：用序列功能安排事件」。

补充：「预期拉扯补遗：两把手、归零开关与多期待并行」 「情绪四阶段与十序列大纲补遗」 「节奏实战：全剧动态分配、过渡直给与节奏感练习」。

## 工作步骤

1. 读取《故事架构文档》《互动设计文档》，确认总集数及时长。
2. 先出整体与分章概要并展示；有未定的关键取舍才问具体问题，用户已授权的内容不重复审批。
3. 再逐章补互动分场（互动节点、分支路径）和章节钩子。
4. 检查选定的终点、行动反馈与可达性；非分支作品不强加多结局。

## 产出：《分集大纲文档》

- 总集数及时长
- 每章概要（核心事件、情绪定位）
- 每章互动分场（含互动节点、分支路径）
- 章节钩子设计
- 多结局设计（详细）

## 集内的节点任务

复杂分支可在一集下面按路径或功能继续拆任务：主线场景、互动点、分支场景、合流、结局。复用 task_write/task_update/task_complete 记录，不新建另一套任务系统。

每个任务写明前置已知事实、目标、选择及后果、状态变化、下一场景。共享场景只写一次，分支特有事实不能不加条件进入合流。按集交付的外层粒度不变；只有任务需要时才细分，用户不必手动触发节点分解。

## 可交互的成果展示

人物用 characters，relationships 的 from/to 引用人物 name，label 写关系，tension 写具体矛盾。大纲用 outline，emotion 标情绪，details 放可展开的细节。需要体验选项后果时用 script 展示无状态短样段：start 对应场景 id，blocks 区分 action 与 dialogue，每个场景以 choices 或 ending 收束；目标必须存在，所有场景可达且无环。完整、有状态的互动剧本照常校验交付，不声称短样段能运行全部状态规则。

用户修改意见产生新稿时，用 revision 提供真实 before、after 和 reason，原稿来自实际已有版本。所有结构均可放入 ask_user.preview 等待反馈，或 show_creative_work 单独展示。页面点人物、展开大纲、试玩选择不提交创作意见；只有明确反馈才代表用户的创作决定。
