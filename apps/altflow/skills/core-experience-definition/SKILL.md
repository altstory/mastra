# 核心体验定义

核心体验帮助团队说明想让用户感到什么、做什么与带走什么。它可通过试写和试玩逐步发现，也可以包含互补的多种体验，不是开始创作前必须完成的门禁。

## 三个层次

1. **情感体验**：用户在体验过程中会感受到什么？例如爽感、虐心、治愈、紧张。
2. **主题或问题**：作品想探索什么经验、矛盾或疑问？可以保持开放，不要求预先给出人生哲理。
3. **参与体验**：用户如何观察、行动与获得回应？选择、探索、动作、制作、协作、表达、照料与等待均可考虑；非互动作品不强加操作机制。

## 提炼方法（任选其一或组合）

- **一句话故事 + 核心体验**：「这是一个关于[核心冲突]的故事，用户会体验到[核心体验]。」
  示例：这是一个关于在乱世中选择善恶的故事，用户会体验到道德抉择的挣扎与后果。
- **关键词法**：用 3 到 5 个关键词概括，如复仇、爽感、快节奏、反转。
- **情感承诺**：用户看完或玩完后，会带走什么感受？

## 工作步骤

1. 先读已有想法与材料，仅询问会影响当前创作的重要缺口；信息够用或用户要求直接推进时开始，没有固定问题配额。
2. 方向未定时给少量有区别的草案或代表场景；已有方向直接细化。三层次是思考角度，不要求每次完整填表。
3. 需要关键取舍时用现有预览和问答工具听取反馈；用户已授权自主创作时说明假设并继续，可混合而非强迫单选。
4. 对选定版本做验证，见下。
5. 汇总成「核心体验描述」，交给环节 1 的《创意构思文档》。

## 验证

| 维度 | 要回答的问题                                     |
| ---- | ------------------------------------------------ |
| 清晰 | 团队能否用一句话复述并达成共识                   |
| 独特 | 与同类作品相比，差异在哪里                       |
| 吸引 | 目标用户为什么会想要它（有无市场验证或直觉依据） |

每个维度给出判断和依据；没有依据的，明确标为「待验证」，不要凭空下结论。

## 产出

- 一句话故事 + 核心体验
- 对当前任务有帮助的情感、主题问题和参与方式
- 必要的体验关键词或代表场景
- 清晰、独特、吸引三项验证结论与待验证项

## 注意

- 核心体验是对用户的承诺，不是对故事情节的概括：写「用户会感到什么、做什么」，不要只写「发生了什么」。
- 与目标受众有关的判断先检查证据来源、样本和适用范围；知识库只是参考，不能把通用标签或别的平台数据当当前项目验证。
- 说明情境中的具体行动与反馈，不把所有互动体验收窄为按钮选择；设计与实际运行能力分开记录。
