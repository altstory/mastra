# 质量检查

目标：确保核心体验被完整传达。

## 方法

- **AI 扮演玩家**：以玩家视角反复回看，判断核心体验是否被感受到。需要独立视角时，交给子智能体做，避免被前面创作的上下文带偏。
- **一致性检查**：角色行为、世界规则、时间线。
- **逻辑验证**：因果关系、动机合理性。
- **情感验证**：情感旅程是否完整、高潮是否有铺垫。
- **互动有效性**：选择是否有意义、反馈是否清晰。
- **分支完整性**：所有分支是否可达、有没有死路。
- **变量正确性**：状态变量是否正确更新。

## 检查清单（按重要性）

1. **核心体验是否完整传达**（最重要）
2. 角色一致性
3. 世界规则一致性
4. 时间线一致性
5. 逻辑连贯性
6. 情感完整性
7. 互动有效性
8. 分支完整性
9. 变量正确性
10. 多结局可达性

## 互动剧专项检查

在上面的清单之外，逐条核对：

- **路线承接**：角色有没有使用本路线尚未展示或获知的线索？合流场景有没有用到只在某一条分支里建立的事实？
- **状态一致**：对白、效果说明和状态标签是否使用同一字段、方向和数值？有没有另造一套加减分？
- **跨集推进**：已确认的发现或身份，有没有在后续集里被当作新发现重复？
- **时间与结果**：依赖某结果的不可逆行动，是否发生在结果建立之后？「打算」有没有被当成「完成」？
- **终局兑现**：每条通向某结局的路线，是否都在正文里演出了关键行动或结果，而不是只复述目标或以悬念代替？
- **去 AI 味**：是否出现「不是 A，而是 B」、「眼中闪过一丝」之类的套话？
- **格式**：用 `validate_script_format` 校验场景编号、互动标记、选项跳转和分支收束。
- **逻辑预警**：时间线冲突（事件先后与时间标注矛盾）、角色能力矛盾（前面做不到的事后面轻松做到，或反之）、伏笔未规划（埋下后没有回收，或回收的东西没有埋过）。发现时标为提醒，写明涉及的场景编号。

## 整体检查：script-qa 工作流

检查一整部或多集的完整剧本时，优先运行 `script-qa` 工作流，而不是自己逐项读：

- 输入：`script`（剧本全文，X-Y 场景编号格式）；有核心体验时一并传入 `coreExperience`；有《互动设计文档》的状态变量清单时传入 `variables`（名称、范围、初始值），才会检查变量是否已定义；《需求确认》里写了创作原则时传入 `principles`（每条一个字符串），会逐条对照；知道项目名时传入 `project`，会再对照该项目的设定与伏笔台账，检查未回收的伏笔和已死亡角色再次出场。台账为空时报告会注明没有做台账检查。
- 它先做格式校验和场景图分析（孤立场景、死路、虚假自由、选项过多、路径膨胀与失衡），再并行做四项模型审查（路线承接与状态、一致性、跨集推进与终局兑现、文笔与核心体验），最后汇总出《质量检查报告》。
- 返回 `passed`、`errors`、`warnings`、`report` 和结构化的 `sections`。界面会把报告画成卡片，你只需概述结论、说明哪些是错误、哪些是提醒，并点出最该先改的几项；不要整段复述报告，也不要自行删减问题。
- 想让用户直观看到分支结构时，用 `show_branch_graph` 展示结构图，图由界面绘制，你只需说明结构特点。
- 只检查几个场景或一小段时，用 `validate_script_format` 和 `analyze_script_graph`（不调用模型，秒回）加上面的清单即可，不必跑整个工作流。
- 保存为项目的 `08-质量检查报告.md`，用户确认修改后再更新剧本并重新检查。

## 互动设计的三个陷阱

- **虚假自由**：多个选项指向同一场景，或目标场景内容 90% 以上相同。修法：合并相同选项、制造有差别的后果，或在收束点用状态让内容有差异。
- **组合爆炸**：任一节点的选项超过 3 个，估算总路径数过大，各路径长度差异悬殊。修法：用纺锤形结构收束，合并相近选项，用状态条件限制可选项。
- **状态遗忘**：设置了却从没读取的标志，选择后续影响很小（不到三成），分支收束太快。修法：在后面的场景补上后续影响，推迟收束，或用计数累积影响。

## 体验平衡与遗忘元素

- 对比不同路径在长度、内容深度、难度和奖励上的差距，差距过大的要补偿或削减。
- 角色、伏笔和支线如果连续很多集没有出现，要提醒用户是否遗忘，或安排回收。
- 需要展开时，用知识库检索「互动体验平衡」「有意义的选择」「玩家心理」。

## 检查分级

按用户的阶段选一档，默认标准档，并告诉用户这次用的是哪一档：

| 档位 | 检查什么                                                                                                 | 什么时候用               |
| ---- | -------------------------------------------------------------------------------------------------------- | ------------------------ |
| 快速 | 格式、场景图与状态标注：`validate_script_format`、`analyze_script_graph`（有变量清单时传入 `variables`） | 写完一场或一集，边写边查 |
| 标准 | 快速档，加状态与逻辑（变量先定义后使用、无互斥状态同时为真、无孤儿标志）、体验量化（见下）、三个陷阱     | 一整集或一条路线写完     |
| 深度 | 标准档，加 `script-qa` 工作流的四项模型审查、台账对照、对照创作原则逐条核对                              | 整部完成、交付之前       |

**体验量化的参考线**：

- 各主要路径的场景数差异不超过 30%，字数差异不超过 40%；差别更大的路径要补充内容或明确标为隐藏路径。
- 选项文字不超过 20 字；除结局外，每个互动至少 2 个选项。
- 不存在明显「偷懒」的短路径。
- 工具只在路径长度差异超过一倍时才报警，30% 到一倍之间靠你判断，作为提醒而不是错误。

**对照创作原则**：项目的《需求确认》里写了创作原则时，深度档要逐条核对：每条原则列出「通过」或「违反」，违反的指出场景编号和原文。没有写明创作原则的项目，不凭空编造原则。

## 工作步骤

1. 先确认检查范围（整部、某几集或某条分支），并读取对应的产出物。
2. 按清单逐项检查，每个问题写明：位置（场景编号）、问题、依据、严重程度。
3. 无法确认的内容标为「需人工确认」，不要凭印象判断。
4. 给每个问题一个具体的修复建议。

## 产出：《质量检查报告》

- 检查结果汇总（按清单逐项给出通过、有问题或待确认）
- 问题列表
- 修复建议

## 按当前任务选择检查深度

局部修改先用 validate_script_format/analyze_script_graph 检查受影响的格式、跳转和状态；整集交付用 script-qa，传入当前需求文档里已确认的 principles、互动设计里的 variables 和 project。发布前再复查跨集承接、结局兑现和关键路径；不声称工具完成了未实现的所有状态组合穷举。

用户没有提供原则或变量时保持明确的未提供状态。调用前先读当前项目的需求确认和互动设计文件，不从旧对话猜测。质检结论以工具实际返回为准，不能承诺检查用时。
