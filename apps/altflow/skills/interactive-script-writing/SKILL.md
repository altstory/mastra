# 互动剧本写作

## 风格

- **对白**：按人物、场景、媒介与文风选择直说、潜台词、沉默或叙述，不要求每句都含蓄或紧张。
- **动作与感官**：写制作和表演能理解的动作、空间与声音；细腻、简洁或留白依作品选择。
- **可选框架**：Scene-Sequel 可帮助组织行动与反应；观察、关系、日常、群像、循环或探索结构也可使用，不强制每场发生灾难。

## 格式与命名

| 对象         | 命名                  | 示例     |
| ------------ | --------------------- | -------- |
| 场景         | X-Y                   | 1-1      |
| 互动节点     | X-Y-互动              | 1-1-互动 |
| 选项分支     | X-Y-A / X-Y-B / X-Y-C | 1-1-A    |
| 选项后的续场 | X-2-A / X-2-B / X-2-C | 1-2-A    |

命名规则在整部作品中保持统一，跳转要明确：每个选项写清楚跳到哪个场景。

## 生成策略

按用户要求、篇幅与可用上下文确定批次：长作品可分集、分场或分路线，短作品可一次完成。分批为连贯性与反馈服务，不设固定半集或单集上限。

## 格式规范（可用 `validate_script_format` 工具校验）

```
第1集 集标题
1-1 场景描述（地点、时间）
△动作描写
角色：台词
1-1-互动 本次互动要用户回答的问题
1-1-A：选项文字 → 1-2-A
1-1-B：选项文字 → 1-2-B
1-2-A 续场描述
……分支内容……
（合流 → 1-3）
1-2-B 续场描述
……分支内容……
（合流 → 1-3）
1-3 场景描述
……
本集结束
```

- 场景编号 `X-Y`：X 是集号，Y 是本集内的场景序号，同集内递增、不重复。
- 互动节点 `X-Y-互动`：紧跟在场景 `X-Y` 的内容之后，一个场景最多一个。
- 选项 `X-Y-A / X-Y-B / X-Y-C…`：字母从 A 连续，每个互动 2 到 6 个选项；每个选项以 `→` 写明跳转的续场编号。
- 续场 `X-(Y+1)-A / X-(Y+1)-B`：与选项一一对应，以场景头形式出现。
- 分支以 `（合流 → 场景编号）`、`（闭合）` 或 `（结局：名称）` 收束，不留悬空。
- 每集以 `本集结束` 收尾。

## 去 AI 味

检查以下表达是否重复、空泛或不符合人物；它们是审读线索，不是逐词禁用表：

- 句式：「不是 A，而是 B」及其否定排比；「，带着……」式万能状语；「仿佛、犹如、宛若……一般」。
- 套路神态：「眼中闪过一丝……」「嘴角勾起一抹……」「心中涌起……」「深吸一口气」「不由得、顿时」。
- 戏剧碎片：「X。就这样。就是这个。」式的强行深刻；空泛的章末预告「他不知道的是……」。
- 改法：用具体的动作、台词和可见细节来呈现，不用总结性的心理词和成堆的比喻；抒情、直述或白描按已确认文风选择。

## 节拍口径

- 节奏由作品目的决定；强情绪可以使用蓄势与爆发，也可通过发现、靠近、等待、照料、平静或失落推进，不强迫每场震惊。
- 收尾可用钩子、局部完成、关系变化或余韵，不强制每集危机或反转。
- 终局集先兑现指定的结局，再留余韵，不以悬念代替答案。
- 互动可通过选择、观察、探索、操作、制作、表达与协作发生；时机服务体验，局部表达不强加代价或长期变量。

## 路线承接与状态描述

- 角色只能使用**本路线**已经展示或明确获知的线索。先演出发现、展示或告知，再提问或采取依赖该线索的行动。其他选项、后续场景和规划摘要里的信息，不等于角色已经知道。
- 合流场景只能使用每条可合流路线都已建立的事实；专属线索留在对应分支里。
- 正向选择之后的承接要保留这个选择的行动和反馈，不得无条件改写成相反的态度。
- 状态变化只采用互动设计里为该选项定义的变化：对白、效果说明和状态标签使用同一字段、方向和数值，不另造一套加减分。没有确定数值时，只写可观察的后果。

## 终局兑现

终局必须在可观看的正文里演出指定结局的关键行动、揭示或结果。只复述目标、写成将来打算、或用新的悬念顶替，都不算兑现。每条通向该结局的路线都要兑现；余韵只能放在兑现之后。

## 工作步骤

1. 读取现有大纲、对应材料与已定义变量；局部试写没有全套前置文档也能开始，明确必要假设。
2. 复用已确认的目标、文风与互动安排，只有影响当前作品的未定取舍才询问。
3. 按所选组织方式写场景，互动描述清楚情境、动作、识别、反馈与必要的后续影响。选择型节点采用现有正式格式；其他动作先提供设计说明，不编造运行器字段。
4. 只记录实际发生且需要持续承接的状态变化；无状态或局部表达不强行增加数值。
5. 正式剧本用 validate_script_format 校验格式与跳转；文风、人物、体验与路线承接另外审读，不能声称格式工具验证了文笔或玩家手感。新型交互未有真实原型时明确待实现、待验证。
