# 故事架构

结构是为核心体验和主角弧光服务的骨架，不是套模板。

## 可用的结构工具

- **三幕结构**：建立 → 对抗 → 解决。
- **布莱克·斯奈德节拍表**：15 个节拍。
- **罗伯特·麦基故事理论**：激励事件 → 进展纠葛 → 危机 → 高潮 → 结局。
- **价值转折**：每个场景都要有价值变化（从什么到什么）。

选择一两个最适合项目的工具，说明为什么，不要一股脑全用。

## 工作步骤

1. 读取前面环节的产出物，重点是核心体验和主角弧光。
2. 选结构工具，先排出整体结构（三幕或多幕）。
3. 标出关键节拍与节点，并写明每个节点上主角处于弧光的哪个阶段。
4. 划分幕和章节，写出**每章的核心体验**（用户在这一章应感到什么）。
5. 检查价值转折：任何一章没有价值变化，要指出并建议合并或重写。
6. 与用户确认后再输出文档。

## 产出：《故事架构文档》

- 整体结构（三幕或多幕）
- 关键节拍与节点
- 幕与章节划分
- 每章核心体验
- 主角弧光与结构的对应

## 按需设计互动拓扑

在写正式剧本前，按核心体验选择结构。先参考已确认的互动密度、结局倾向和制作规模，不让用户必须认识结构名。

| 结构   | 创作取舍                                       |
| ------ | ---------------------------------------------- |
| 树状   | 选择长期分开，后果鲜明，但内容量增长快         |
| 纺锤形 | 分支后合流，控制制作量；合流必须承认之前的选择 |
| 网状   | 适合调查和探索，需要检查循环、可达性和信息顺序 |
| 枢纽式 | 主场景连接人物或地点路线，需要明确回归条件     |

只在取舍尚未明确时用 ask_user 提问。设计文档可用 Mermaid 记录节点与边；需要在对话展示时，以 Altflow 的 X-Y 场景编号、选项跳转和合流标记表达同一结构草案，交给 show_branch_graph 绘制。说明这是结构草案，不伪称已经写完剧本。不要把 my-novel 的 N001/END_GOOD 格式直接用于 Altflow 工具。
