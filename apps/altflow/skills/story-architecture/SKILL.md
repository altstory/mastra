# 故事架构

结构是为核心体验和主角弧光服务的骨架，不是套模板。

## 可用的结构工具

- **三幕结构**：建立 → 对抗 → 解决。
- **布莱克·斯奈德节拍表**：15 个节拍。
- **罗伯特·麦基故事理论**：激励事件 → 进展纠葛 → 危机 → 高潮 → 结局。
- **价值转折**：诊断关键场景如何改变局面；铺垫、观察、休息与日常仪式也可承担关系或理解的推进，不要求每场强反转。
- **其他组织方式**：单元、群像、循环、片段、空间探索、事件与状态驱动。按作品目标与制作条件选择，不要求套进三幕或 15 节拍。

方法可组合，也可从代表场景归纳结构；解释当前方法解决什么问题，不按理论清单补齐所有节拍。

## 工作步骤

1. 读取已有材料与用户目标，重点是体验、人物、关系或待解决的结构问题；不要求先完成全套前置文档。
2. 选择合适的组织方式；已有故事先诊断，不为了套框架重排全部内容。
3. 标出关键变化与节点，追踪人物、关系、世界或玩家认知如何发展；人物可以成长、坚守、衰退或保留矛盾。
4. 划分幕和章节，写出**每章的核心体验**（用户在这一章应感到什么）。
5. 检查章节是否承担信息、行动、情绪、关系、节奏或理解上的作用；确实重复且无功能再建议合并，不因缺少强反转判错。
6. 展示并保存已授权的成果，只有未定的重要取舍才提问。

## 产出：《故事架构文档》

- 整体组织方式与选择理由
- 关键节拍与节点
- 幕与章节划分
- 每章核心体验
- 主角弧光与结构的对应

## 按需设计互动拓扑

在写正式剧本前，按核心体验选择结构。先参考已确认的互动密度、结局倾向和制作规模，不让用户必须认识结构名。

| 结构   | 创作取舍                                       |
| ------ | ---------------------------------------------- |
| 树状   | 选择长期分开，后果鲜明，但内容量增长快         |
| 纺锤形 | 分支后合流，控制制作量；合流必须承认之前的选择 |
| 网状   | 适合调查和探索，需要检查循环、可达性和信息顺序 |
| 枢纽式 | 主场景连接人物或地点路线，需要明确回归条件     |

只在取舍尚未明确时用 ask_user 提问。设计文档可用 Mermaid 记录节点与边；需要在对话展示时，以 X-Y 场景编号、选项跳转和合流标记表达同一结构草案，交给 show_branch_graph 绘制。说明这是结构草案，不伪称已经写完剧本。不要把 N001/END_GOOD 这类节点编号格式直接交给工具。
