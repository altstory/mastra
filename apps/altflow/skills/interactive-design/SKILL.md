# 互动设计

互动要服务核心体验：用户的每次选择都应让核心体验更强，而不是打断叙事。

## 要素

- **互动维度**：深层（价值观选择）和浅层（机制互动）。
- **选项机制**：2 选 1 与 3 选 1 的取舍、沉默选项、隐藏选项。
- **分支结构**：线性加小分支、汇聚型、平行型。
- **状态变量**：关系值、剧情标记、资源变量、隐藏变量。
- **反馈层次**：短、小中、中中、大中、长反馈，即选择之后多久、以多大的方式被看见。
- **互动密度**：基准为 1 分钟 1 个互动，按核心体验灵活调整。
- **多结局**：失败结局、中间结局、最终结局。

## 选项设计框架

铺垫 → 激发 → 选项 → 反馈 → 后续影响。每个重要选项都按这五步写清楚。

## 四类主互动体验

先判断作品的**主互动体验**，再按它的口径设计互动。题材、人群只是辅助标签，影响语言风格，不决定设计方向。

| 主互动体验 | 用户的感受       | 设计侧重                                                                       | 必备状态                       |
| ---------- | ---------------- | ------------------------------------------------------------------------------ | ------------------------------ |
| 情感抉择   | 我来决定关系走向 | 关系推进、情绪反馈、选择与被选择；按钮文案要带情感动作，避免「选 A / 选 B」    | 好感、信任、误会               |
| 命运逆转   | 我来改写主角人生 | 关键转折、打脸、逆袭路径；选择发生在命运变化之前，改命要有代价或反噬           | 命运节点、关键资源、身份暴露度 |
| 权谋博弈   | 我来选阵营和策略 | 阵营、信息差、局势变化、利益交换；选策略而不是选胜负，可延迟反馈但要留因果提示 | 阵营、筹码、信任、风险         |
| 生存闯关   | 我来决定能不能活 | 资源、风险选择、关卡推进、代价与奖励；可以有惩罚，但不默认不可恢复的死局       | 生命或体力、资源、危险等级     |

各类体验的可选状态、选项数量、反馈时机与结尾钩子倾向，见知识库页面「四类主互动体验设计要点」。

## 四个设计维度

设计互动时，依次回答四个问题：

1. **节奏**：互动什么时候出现、出现多少、分支多长。
2. **钩子**：用户为什么想继续选、继续看。
3. **选择机制**：用户具体在选什么，选项怎么写。
4. **状态与反馈**：选择改变什么，反馈怎么被看见。

每个维度对应的具体问题清单（按四类体验分别改写）见知识库页面「互动设计四维度问题清单」。

## 节点与连线类型

画分支结构图时，节点分七类：剧情、互动、选项、反馈、合流、状态、钩子；连线分六类：剧情流转、选择、反馈、合流、状态继承、钩子衔接。用统一的类型名，方便后续大纲和剧本对应。

## 分支结构怎么选

| 结构                               | 创作难度 | 内容可控性 | 适合篇幅                     |
| ---------------------------------- | -------- | ---------- | ---------------------------- |
| 树形                               | 低       | 难         | 短篇                         |
| 纺锤形（早分叉、中收束、后再分叉） | 中       | 易         | 中长篇，多数互动剧的推荐选择 |
| 网状                               | 高       | 中         | 长篇、探索解谜               |
| 星形（中心加放射分支）             | 低       | 易         | 中篇、攻略类                 |

分支数量要克制：起始节点 2 到 3 个选项，普通节点 2 个，关键决策最多 3 个，前期选择不超过 3 个，避免组合爆炸。

## 结构图与路径设计

画分支结构图时用 Mermaid 流程图，节点用统一的类型名和编号。图后写三样东西：

- **节点统计**：场景总数、互动节点数、合流点数、结局数。
- **路径设计**：主线路径（节点序列和长度），每条分支路径（从哪个选择分出、在哪里合流、通向哪个结局）。
- **收束点**：每个合流点接住哪几条分支、合流后各路线靠什么状态区分，避免合流后内容完全相同。

默认推荐纺锤形；先选结构，再画图，不要边写边长。剧本写出来之后，用 `show_branch_graph` 把真实的分支结构画给用户看，和设计时的结构图对照。

## 状态变量命名

数值用 `SV_` 前缀（0 到 100），事件标志用 `FLAG_`，累计次数用 `COUNTER_`；变量名要表意（`FLAG_found_key`，不是 `FLAG_event1`）。变量可以可见、隐藏或先隐藏后揭示。每个变量都要写清取值范围、初始值和作用范围；所有变更都要能追溯到具体的选项；生死之类互斥的状态不能同时为真。

## 风险自查

设计完成后，检查是否存在：**假选择**（选哪个结果都一样）、**反馈弱**（选完看不到变化）、**状态无差异**（不同选择没有留下不同状态）、**分支难合流**、**缺少所属的主互动体验**。发现问题，指出位置并给出修改方案。

## 工作步骤

1. 读取核心体验和《故事架构文档》。
2. 先定互动维度和分支结构，再定选项机制。
3. 列出状态变量清单：名称、含义、初始值、被哪些选择改变。
4. 按反馈层次为关键选择规划反馈。
5. 规划互动密度；指出哪里互动过多会打断叙事、哪里过稀会让体验变弱。
6. 设计多结局及触发条件。
7. 自查：每个选项是否有意义（不同选择是否真的带来不同后果）？有没有永远没人选的选项？

## 把选择拿给用户体验

在展开全部变量和分支前，先拿一个代表性互动点示范「情境、选项、即时反馈、后续代价」。可用 ask_user.preview 的 directions 对比不同互动方案，或 excerpt 展示可读的场景试写，再问具体取舍。不要只让用户选择抽象结构名，也不要把完整互动设计悄悄保存后直接写大纲。已有剧本用 show_branch_graph 展示真实分支。已明确授权的细化直接推进，有意义的成果用 show_creative_work 展示。
