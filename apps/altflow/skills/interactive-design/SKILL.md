# 互动设计

从用户想体验什么、玩家实际做什么开始，选择服务当前作品的机制。体验可以混合、变化，不局限于情感抉择、命运逆转、权谋博弈或生存闯关；不确定时先依据已有场景提出假设，不默认归入恋爱。

## 先区分叙事目的与操作方式

叙事目的可以是理解一个人、发现真相、表达自己、照顾同伴、掌握技艺、协商分工或改写命运。操作方式可以是点选、移动、排列、搜索、触碰、演奏、等待或共同操控。同一动作可服务不同题材，同一题材可组合多种动作。

先用一个代表场景写清：**情境与意图 → 玩家动作 → 系统识别 → 即时回应 → 持续影响**。动作可以只带来局部表达与理解，不必每次新增路线或改变结局；不要承诺不存在的后果。

## 行动规格

- 对象与输入：玩家操作什么、怎样操作、如何知道可以操作。
- 条件与反馈：何时可操作，成功、失败、取消、无输入与重复触发如何处理。
- 持续影响：改变信息、关系、空间、资源、行动条件还是仅改变当前表达，后续在哪里体现。
- 成本与恢复：需要哪些文本、音画、交互组件；如何重试、暂停、恢复及提供合适的替代输入。

亲密、照料、调查、竞争等情境采用各自的意义与边界，不把全部行动折算为好感。无输入不能无依据地当成同意，技术故障不能当成角色决定。

## 机制与结构按需组合

| 方法                 | 适用取舍                                                       |
| -------------------- | -------------------------------------------------------------- |
| 对话或决策选择       | 比较明确的行动与代价；选项数量依据可理解性、工具能力和内容规模 |
| 探索与搜索           | 用观察顺序和线索理解推进；检查关键资料可达与错误理解的纠正渠道 |
| 动作与物件操作       | 通过时机、空间、排列或维持表达体验；需要可感知反馈与操作容错   |
| 制作、照料与日常仪式 | 用重复中的变化表现关系；无新意义的重复可以简化                 |
| 时间、资源与调度     | 让行动安排产生机会成本，区分计划和已完成结果                   |
| 协作与非对称信息     | 不同角色相互依赖，明确信息共享、冲突裁决与单人替代             |

树状适合短范围内后果长期分开的故事；纺锤形以合流控制成本；枢纽式适合反复访问人物与地点；网状或状态驱动结构适合探索与系统反应。可以组合，也可以先做单场原型再选择整体结构。不要默认所有项目都用纺锤形。

2 到 3 个选项是紧凑决策场景的一种起点，不是全部互动的上限。互动密度以阅读、观察、操作和反馈所需时间评估，不规定每分钟或每集的固定数量。单结局、局部变化、多结局与开放终点都可成立，按已确认的作品目标选择。

## 状态与信息

只记录会被用到的状态，写清初始值、范围、更新事件、后续读取与失效条件。区分世界当前状态、已发生的行动历史、玩家知道的信息与角色相信的事情；合流不能把未走路线的事实带入当前路线。

对接现有状态剧本时复用其约定：数值用 SV_（0 到 100），事件标志用 FLAG_，累计次数用 COUNTER_；名称应表意。各类输入、道具或时间系统的设计概念不等于运行器已支持相应字段，额外数据结构先明确为待实现设计。互斥状态不能同时成立，状态变化必须能追溯到真实发生的行动或事件。

## 结构与成果展示

设计阶段可用 Mermaid 记录节点、动作、状态与连线，说明主路径、分支、合流条件及终点。状态驱动或循环设计另外说明触发与退出规则，不能用无状态树图假装完整模拟。已有受支持格式的剧本用 show_branch_graph 展示真实分支。

先用 ask_user.preview 的 directions、excerpt 或 document 展示可评价的动作场景或机制对比；仅在存在影响后续的未定取舍时提问。已授权的细化直接推进，用 show_creative_work 展示成果。动作原型可用分镜或说明文档交付，不用抽象术语代替示例。

## 工具能力边界

script 预览能展示受支持的无状态选择样段，action 是场景描述，不是可执行的拖拽、QTE、语音识别或多人联机。需要新交互时说明已设计、待做原型、待实现的部分；不编造工具字段或把模拟结果说成真实运行。放宽创作方法不放宽工具 schema、鉴权、素材保密与交付验证。

## 知识库参考

按当前问题检索「互动动词与行动反馈：不止按钮选择」「动作与物件操作：力度、时机、空间」「探索与环境叙事：地点、痕迹和好奇心」「搜索、解谜与证据操作的互动设计」「对话中的行动：倾听、节奏、姿态与表达」「照料、制作与日常仪式的互动」「协作与非对称互动：共同动作而非轮流投票」「失败、部分成功与继续推进」「世界事实、行动历史与角色认知」「互动可访问性与节奏：让更多人能参与」「互动原型与制作预算：设计不等于实现」。旧的四类体验和节点类型组只是局部参考，不是分类门禁。不在用户回复中列出内部资料或复述原文。

补充：「信息差实战补遗：落差大小、势能累积、知情配置与共享秘密」 「情绪曲线设计：定点配事、叠加、阻断与分阶段兑现」。

## 自查与产出

检查玩家是否理解动作、是否获得承诺的反馈、重要状态是否被承接、失败是否有合理处理、制作成本是否可控。表达型动作或路径合流本身不是错误，需结合承诺与实际体验判断。

《互动设计文档》按需包含体验目标、代表场景、行动规格、结构、状态、反馈、节奏、终点与制作需求。没有多结局、数值或分支的作品不强行补齐这些栏目。

## 可交互的成果展示

人物用 characters，relationships 的 from/to 引用人物 name，label 写关系，tension 写具体矛盾。大纲用 outline，emotion 标情绪，details 放可展开的细节。需要体验选项后果时用 script 展示无状态短样段：start 对应场景 id，blocks 区分 action 与 dialogue，每个场景以 choices 或 ending 收束；目标必须存在，所有场景可达且无环。完整、有状态的互动剧本照常校验交付，不声称短样段能运行全部状态规则。

用户修改意见产生新稿时，用 revision 提供真实 before、after 和 reason，原稿来自实际已有版本。所有结构均可放入 ask_user.preview 等待反馈，或 show_creative_work 单独展示。页面点人物、展开大纲、试玩选择不提交创作意见；只有明确反馈才代表用户的创作决定。
