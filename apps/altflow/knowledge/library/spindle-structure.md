# 纺锤形结构（Spindle Structure）

## 概述

纺锤形结构（也叫漏斗形结构）是互动叙事中最实用的结构类型。其特点是"分久必合"——早期分叉让玩家做出选择，中期收束控制内容量，后期再分叉至不同结局。

---

## 结构形态

```
        START (1个)
         /  \
      N001   N002  (早期分叉)
       |     |
      N003   N004
       |     |
      N005   N006
         \   /
          N010   (收束点)
         / |  \
     N011 N012 N013  (再分叉)
      |    |    |
    END_A END_B END_C
```

---

## 核心特点

### 1. 早期分叉（Divergence）

**时机**：故事前1/3
**目的**：让玩家做出初始选择
**分支系数**：2-3个选项

**示例**：
```
第一章：
- 选择A：理性分析路线
- 选择B：情感体验路线
- 选择C：中立观察路线
```

### 2. 中期收束（Convergence）

**时机**：故事中段
**目的**：控制内容总量，统一叙事方向
**收束频率**：每3-5个节点

**示例**：
```
第五章：
- 无论之前如何选择，角色们都来到了同一地点
- 使用条件文本体现差异
- 继续主线剧情
```

### 3. 后期再分叉（Final Divergence）

**时机**：故事后1/3
**目的**：导向不同结局
**分叉基础**：基于之前的选择累积

**示例**：
```
第十章：
- 基于玩家全过程的SV和FLAG
- 判定进入哪个结局分支
- 每个结局有其独特价值
```

---

## 优势

### 1. 内容可控

**问题**：树状结构内容量指数增长
**解决**：收束点复用内容

**对比**：
```
树状（3层，每层2分支）：
1 → 2 → 4 → 8 = 需要15个节点

纺锤形（2层分叉 + 收束 + 再分叉）：
1 → 2 → 4 → 收束 → 2 = 需要9个节点
节省40%内容量
```

### 2. 叙事连贯

**问题**：多路径难以维持统一主线
**解决**：收束点确保主线推进

**示例**：
```
所有路径在N010汇合：
- 主角到达核心场景
- 推进主线剧情
- 为后续分歧做准备
```

### 3. 创作可行

**问题**：复杂结构难以驾驭
**解决**：模块化创作，分而治之

**工作流**：
```
模块A：N001-N005（分支A）
模块B：N001-N005（分支B）
公共模块：N010（收束点）
模块C：N011-N015（后续A）
模块D：N011-N015（后续B）
```

## 设计要点

### 收束点设计

#### 时机选择

**频率**：每3-5个节点
**位置**：章节结束时、重大事件后

**示例**：
```
第一章结尾：CP01（所有路径汇合）
第三章中间：CP02（临时汇合）
第五章结尾：CP03（终局前汇合）
```

#### 处理策略

**策略1：模糊化处理**
```markdown
## N010（收束点）
你经历了[时间]的旅程，现在来到了[地点]。
无论之前如何，你都需要面对[新挑战]。
```

**策略2：条件文本**
```markdown
## N010
{if path_from == "PATH_A"}
你从理性分析的角度理解了情况...
{else}
你从情感体验的角度感受了情况...
{endif}

无论如何，现在你需要做出决定。
```

**策略3：状态反馈**
```markdown
## N010
{if SV_affection > 60}
她对你的好感明显增加。
{else}
她对你的态度保持礼貌。
{endif}

"我需要你的帮助，"她说。
```

### 分支设计

#### 早期分支

**目的**：建立不同的体验基调

**示例**：
```
PATH_A（理性路线）：
- 强调分析、推理
- SV_confidence影响
- 选项更直接

PATH_B（感性路线）：
- 强调感受、体验
- SV_affection影响
- 选项更温和
```

#### 后期分支

**目的**：基于累积状态导向结局

**示例**：
```
结局判定：
- SV_affection >= 70: END_GOOD
- SV_affection <= 20: END_BAD
- FLAG_all + SV_morality >= 80: END_TRUE
```

## 常见问题

### 问题1：收束点生硬

**表现**：玩家明显感觉到"被强行归拢"

**原因**：
- 收束点处理不当
- 完全无视玩家选择
- 突兀的场景转换

**解决**：
1. 使用条件文本保持差异
2. 给予状态反馈
3. 让收束成为叙事的一部分

### 问题2：差异消失

**表现**：收束后之前的差异完全消失

**原因**：
- FLAG未正确传递
- 条件文本未使用
- 状态被重置

**解决**：
1. 检查FLAG的保存和传递
2. 在收束点后继续使用条件文本
3. 避免重置状态

### 问题3：内容单调

**表现**：所有路径体验相似

**原因**：
- 过度复用内容
- 缺乏差异化
- 收束过于频繁

**解决**：
1. 平衡复用和差异化
2. 在分支段给予足够独特性
3. 适当延长分支路径

## 使用场景

### 最适合

- 中长篇作品（5-20万字）
- 多结局但主线明确
- 需要控制创作成本
- 第一次创作互动小说

### 不适合

- 短篇（<1万字）→ 用树状更简单
- 大型解谜（>20万字）→ 考虑网状
- 约会模拟 → 用星状更合适

## 设计模板

### 基础模板

```
第1-3章：早期分支
├── N001（起点）
├── N002-N004（分支A）
├── N005-N007（分支B）
└── N008-N010（分支C，可选）

第4-6章：首次收束
└── N020（收束点1）
    ├── N021-N023（收束后A）
    ├── N024-N026（收束后B）
    └── N027-N029（收束后C）

第7-9章：再次收束
└── N040（收束点2）
    └── N041-N050（共享主线）

第10-12章：终局分叉
├── N060-N070（结局A路线）
├── N080-N090（结局B路线）
└── N100-N110（结局C路线）

第13章：结局
├── END_A
├── END_B
├── END_C
└── END_TRUE（隐藏）
```

## 最佳实践

### DO（应该做）

✅ 每章结束时考虑收束
✅ 收束点使用条件文本
✅ 给予状态反馈
✅ 控制分支系数≤3
✅ 早期分支可稍多
✅ 后期分支谨慎

### DON'T（不应该做）

❌ 收束点完全无视差异
❌ 过于频繁收束（每节点都收束）
❌ 收束后差异消失
❌ 强行合并不合理的路径
❌ 收束点生硬转换
